# 实施路线

当前交接状态见 [迁移与续做清单](handoff.md)，下文保留各阶段的实施背景。

设计基线：[已确认的交互原型](design/index.html)，用户于 2026-10-22 确认。后续以此稿的暖白、柔橙、衬线字体、顶部标签优先为准，不沿用早期无衬线或任务菜单优先方案。

## 阶段 1

交付状态：真实 ChatGPT 小窗与独立登录已完成，用户确认登录成功，已实测重启后保持登录。快捷键已取消绑定并持久化。

本地窗口与远程网页分离，采用 Electron `BrowserWindow` + `WebContentsView`。本地外壳占顶部 80 px，主进程调整网页原生视图边界；设置打开时隐藏网页视图而不销毁，不靠 DOM z-index 穿透原生网页。

默认 520 × 640。首次按鼠标定位；已有窗口恢复当前位置。选区定位函数已共用，但取词入口不在本阶段接入。放大使用当前显示器工作区，恢复原尺寸；未置顶时整个应用失焦隐藏，登录子窗口和原生对话框不误隐藏。

快捷键默认不绑定；设置支持绑定、修改及取消。用户的 `⌥Space` 已供 Raycast 使用，不能作为小窗的默认值或验收按键。

阶段 1 原先无任务启动不加载网页；0.2.1 调整为启动直接进入上次目标的新对话；0.2.2 将待命页扩展为启用预设涉及的网站各一份。同一持久分区保存登录，不保存任务列表或完整聊天副本。退出时提示当前页面会关闭。

阶段 1 不创建假的预设 / 多任务控件，也不先接 selection-hook 或写网站输入框选择器。登录后的待发送动作随阶段 2 的适配器一起实现。

## 阶段 2

当前状态：已实现通用划词、动作条、预设配置及 ChatGPT 完整填入 / 单次发送。直接依赖 `selection-hook@2.1.2`（MIT），无需自研取词引擎。预设排序使用列表顺序，当前目标固定为 ChatGPT。

已复核 selection-hook 的 macOS 辅助功能路径、许可和版本，使用通用动作条，不写四套应用补丁。模拟复制只能显式开启；不把每次划词变成剪贴板写入。动作条不抢源应用焦点。

预设包含 id、名称、模板、目标、发送方式、需要选区、启用状态、排序。普通预设「问 AI」默认先编辑；解释、总结、翻译默认直接发送；无选区可运行整理待办。目标首版仅 ChatGPT，配置收在设置里。

`ChatGPTAdapter` 集中管理新对话、输入框就绪、完整填入、提交一次、对话链接、标题、草稿与运行状态。先编辑停在网页输入框，不增加本地中转层。登录后再执行待发送动作；结构变化或提交结果不明确时保留内容，不重复发、不截断、不自动拆分。

阶段 2 交付时为单网页，替换已有内容前确认；阶段 3 已将此入口改成独立任务，不再替换旧页面。

本机监听启动成功，用户确认动作条出现；真实 ChatGPT 已验证 14,208 字符多行文本完整填入且不发送，完整预设执行流程中的直接发送得到一条对应提问和一条回复。配置持久化和实际界面已检查；独立启动 Electron 后的辅助功能授权已完成，监听为 active。未逐项验证的应用兼容、全新登录等待流程、网站异常分支保留到阶段 4。

## 阶段 3

已实现顶部自适应标签、原生溢出菜单、独立任务页面与回收流程；真实网站恢复的最终验收仍受 ChatGPT 历史接口 HTTP 403 阻塞。`tasks.ts` 管理页面、执行与生命周期；窗口层只投影当前任务状态。

`TaskManager` 为唯一任务状态所有者。执行状态与页面驻留分开；只在本次运行中保存任务。按当前窗口宽度排列标签，当前任务保持可见；下拉框仅列溢出任务，放大后重新布局。

每个任务一个网页视图，共享网站登录。切换不重载；后台生成继续。任务浮层必须由原生视图层次实现，不能仅提高 DOM z-index。

闲置默认 10 分钟，只有后台、明确完成、无草稿 / 附件编辑 / 待确认、有恢复链接的页面可回收。运行中、等待、未知不回收。恢复仅打开原链接，不重发提示词。关闭运行中、等待、未知或含草稿的任务需要确认。退出不恢复任务列表。

真实验证中，对话链接曾短暂返回无法加载，网站重试后恢复。因此释放前最多使用一个临时隐藏页确认最新一次历史请求成功、链接与最新回答 ID 一致；失败保留原页面，10 分钟后重查。检查过程中原页若变为当前任务、收到编辑或开始新回答，取消这次释放。网站完成标记或回答标识不明确时继续保留。

已验证并发发送 / 编辑、后台回答完成、切换不重载、新任务不带入旧草稿、草稿取消关闭、五任务溢出及下拉切换，以及窄窗 / 宽窗重排。回收门槛用受控时间验证，完整资源观察仍在阶段 6。最终版本按原链接读回同一回答，提问数量仍为一条；随后的独立恢复检查失败，正确保留了原页面。最终版本完整的「自动释放 → 点击标签恢复」成功链路仍需网站历史读取稳定后补验，不把 403 页面视为可回收。

## 阶段 4—6

2026-10-22 用户确认新顺序：本地 CLI 与应用提示词 → Gemini 与单图 → 集中验收和安装。完整需求和实现接口见 [后续阶段设计](next-phases-design.md)。

原阶段 1—3 的验收记录保留为历史证据，不代表新增功能已经验收。本轮状态见 README 的验收部分。

## 原有路径打磨（0.2.1）

本轮范围：启动直接进入默认目标、网页预热、预设模型与思考强度、本地聊天增量更新、短过渡动效。截图能力独立后续实施，既有剪贴板图片不变。

`TaskManager` 仍为任务与资源所有者；0.2.2 起按启用预设的网站及上次网页目标各保留一个待命页、10 分钟过期，实际任务生成和草稿保护沿用原规则。设置中的模型读取不操作当前任务页面。临时 Pi 元数据进程也由主进程跟踪并在退出时清理。

模型与强度为预设可选字段，旧预设沿用目标默认；跨目标临时覆盖不沿用原模型。网页适配器先选择并核对，自动发送前再次核对；失败保留待处理内容。CLI 使用原生协议并读回支持档位。消息流只发送变化消息，外壳状态独立发布。

实现后的架构与调用链已复核，定向及真实 CLI 证据见 README。真实网页模型菜单和动画仍受桌面控制连接不可用影响；生成安装包不等于安装后验收通过。

## 0.2.2 启动与开发授权

预热集合来自已启用预设的网站与上次网页目标，每站最多一个待命页。启动与保存预设时同步集合；接管页面后延迟补充，10 分钟未使用释放。待命页不成为任务，不提交预设，不启动本地 CLI；模型目录读取中的页面不被抢占或随预设停用销毁，结束后再清理。

打包复用钥匙串中的本机开发证书 `Lasso Local Development`，由 `@electron/osx-sign` 按嵌套顺序签名。缺证书就停止打包，不退回 ad-hoc。首次迁移重新授予权限；后续验收使用固定路径的安装版，保留原 userData。已实际验证不同代码构建替换后，原生划词监听无需再次授权即恢复 `active`。

## 0.2.3 网页模型与动效

网页适配集中在 `WebProfile`：ChatGPT 的模型列表与强度滑杆分视图操作，Gemini 按模式菜单及思考等级子项读取。强度按网页原生选项枚举、恢复，不用固定模型表。关闭菜单等待真实收起，同站目录请求串行，重复请求合并。

`TaskManager` 为隐藏待命页和新建准备页提供桌面视口覆盖，必须等渲染器就绪后启用，实际显示时关闭覆盖。页面显隐变化才触发原生网页内容过渡，不随状态广播反复播放。React 外壳负责设置分类、预设表单和指示线动效；原生窗口负责整个小窗淡入淡出。实际网页选项、完整编辑预设和动效证据见 README。

## 技术依据

- [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)：原生网页视图。
- [Electron 安全要求](https://www.electronjs.org/docs/latest/tutorial/security)：隔离远程内容，不开放 Node 和本地 IPC。
- [globalShortcut](https://www.electronjs.org/docs/latest/api/global-shortcut)：全局注册及冲突结果。
