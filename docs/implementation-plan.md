## 阶段 1

交付状态：真实 ChatGPT 小窗与独立登录已完成，用户确认登录成功，已实测重启后保持登录。快捷键已取消绑定并持久化。

本地窗口与远程网页分离，采用 Electron `BrowserWindow` + `WebContentsView`。本地外壳占顶部 80 px，主进程调整网页原生视图边界；设置打开时隐藏网页视图而不销毁，不靠 DOM z-index 穿透原生网页。

默认 520 × 640。首次按鼠标定位；已有窗口恢复当前位置。选区定位函数已共用，但取词入口不在本阶段接入。放大使用当前显示器工作区，恢复原尺寸；未置顶时整个应用失焦隐藏，登录子窗口和原生对话框不误隐藏。

快捷键默认不绑定；设置支持绑定、修改及取消。用户的 `⌥Space` 已供 Raycast 使用，不能作为小窗的默认值或验收按键。

无任务启动不加载网页。首次点击进入 ChatGPT；同一持久分区保存登录。仅持久化快捷键，不保存任务或网页草稿。退出时提示当前页面会关闭。

阶段 1 不创建假的预设 / 多任务控件，也不先接 selection-hook 或写网站输入框选择器。登录后的待发送动作随阶段 2 的适配器一起实现。

## 阶段 2

当前状态：已实现通用划词、动作条、预设配置及 ChatGPT 完整填入 / 单次发送。直接依赖 `selection-hook@2.1.2`（MIT），无需自研取词引擎。预设排序使用列表顺序，当前目标固定为 ChatGPT。

已复核 selection-hook 的 macOS 辅助功能路径、许可和版本，使用通用动作条，不写四套应用补丁。模拟复制只能显式开启；不把每次划词变成剪贴板写入。动作条不抢源应用焦点。

预设包含 id、名称、模板、目标、发送方式、需要选区、启用状态、排序。普通预设「问 AI」默认先编辑；解释、总结、翻译默认直接发送；无选区可运行整理待办。目标首版仅 ChatGPT，配置收在设置里。

`ChatGPTAdapter` 集中管理新对话、输入框就绪、完整填入、提交一次、对话链接、标题、草稿与运行状态。先编辑停在网页输入框，不增加本地中转层。登录后再执行待发送动作；结构变化或提交结果不明确时保留内容，不重复发、不截断、不自动拆分。

阶段 2 交付时为单网页，替换已有内容前确认；阶段 3 已将此入口改成独立任务，不再替换旧页面。

本机监听启动成功，用户确认动作条出现；真实 ChatGPT 已验证 14,208 字符多行文本完整填入且不发送，完整预设执行流程中的直接发送得到一条对应提问和一条回复。配置持久化和实际界面已检查；独立启动 Electron 后的辅助功能授权已完成，监听为 active。未逐项验证的应用兼容、全新登录等待流程、网站异常分支保留到阶段 4。

## 阶段 3

已实现顶部自适应标签、原生溢出菜单、独立任务页面与回收流程；真实网站恢复的最终验收仍受 ChatGPT 历史接口 HTTP 403 阻塞。`tasks.ts` 管理页面、执行与生命周期；窗口层只投影当前任务状态。

`TaskManager` 为唯一任务状态所有者。执行状态与页面驻留分开；只在本次运行中保存任务。按当前窗口宽度排列标签，当前任务保持可见；下拉框仅列溢出任务，放大后重新布局。

每个任务一个网页视图，共享网站登录。切换不重载；后台生成继续。任务浮层必须由原生视图层次实现，不能仅提高 DOM z-index。

闲置默认 10 分钟，只有后台、明确完成、无草稿 / 附件编辑 / 待确认、有恢复链接的页面可回收。运行中、等待、未知不回收。恢复仅打开原链接，不重发提示词。关闭运行中、等待、未知或含草稿的任务需要确认。退出不恢复任务列表。

真实验证中，对话链接曾短暂返回无法加载，网站重试后恢复。因此释放前最多使用一个临时隐藏页确认最新一次历史请求成功、链接与最新回答 ID 一致；失败保留原页面，10 分钟后重查。检查过程中原页若变为当前任务、收到编辑或开始新回答，取消这次释放。网站完成标记或回答标识不明确时继续保留。

已验证并发发送 / 编辑、后台回答完成、切换不重载、新任务不带入旧草稿、草稿取消关闭、五任务溢出及下拉切换，以及窄窗 / 宽窗重排。回收门槛用受控时间验证，完整资源观察仍在阶段 4。最终版本按原链接读回同一回答，提问数量仍为一条；随后的独立恢复检查失败，正确保留了原页面。最终版本完整的「自动释放 → 点击标签恢复」成功链路仍需网站历史读取稳定后补验，不把 403 页面视为可回收。
