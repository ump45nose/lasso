# 阶段 4—6：已确认的实施设计

2026-10-22 设计基线；当前进度与迁移见 [交接清单](handoff.md)。定位：开发时随手处理轻任务，复用网站和 CLI，不另造执行引擎。

## 阶段 4：本地 CLI 与应用提示词

- 目标为 ChatGPT / Gemini / Codex / Pi；预设设置或二级菜单选择，动作条只放预设。TaskManager 唯一管理任务生命周期；AgentSession 管理该任务的 CLI 协议状态。
- 应用背景按 bundle ID 匹配，设置支持选应用、手动填写、启停和编辑。只在明确划词来源时组合“应用背景 → 预设内容”。无选区、剪贴板图片和普通追问不注入。
- Codex 使用独立 `app-server --listen stdio://`，多个任务共用服务、独立 thread。Pi 每任务一个 `--mode rpc` 子进程。沿用用户配置和原生权限，不修改全局配置。
- 设置保存 CLI 绝对路径和默认目录（用户主目录）；新任务可临时选择目录。Node CLI 解析真实入口及 Node 路径，参数不经 shell，提示词只经协议。
- 本地 React 聊天提供 Markdown、代码块、工具进度、模型、停止、审批和提问。Pi confirm/select/input/editor 映射控件；终端专属 UI 不承诺移植。生成时可写下一条草稿，结束或停止后再发送。
- 消息通过独立 agent IPC 更新，不进入 ShellState。Pi 以 agent_settled 判定自动执行结束，不以 ACK 或 agent_end 判定完成。

## 阶段 5：Gemini 与单张剪贴板图片

- Gemini 使用自己的持久登录分区；网页继续拥有账号、模型、附件和聊天。网页先编辑直接填入网页，无本地文字中转。
- Google 内嵌登录存在限制，登录与重启保持必须实测；失败只阻塞 Gemini，不静默换 API 或复制浏览器凭据。
- 剪贴板图片只在用户主动粘贴或点击时读取，冻结原尺寸 PNG；预览、移除、替换，再运行预设。首批一张，不内置截图、OCR、标注或多图。
- 图片由主进程管理；界面只有 ID、尺寸、缩略图。ChatGPT/Gemini 复用网站附件入口；Codex 使用 localImage，Pi 使用 RPC image。
- 网站完成附件上传、完整填入文字后才按模式发送。失败保留内容，不丢图只发文字，不自动重复提交。
- 待处理图片阻止闲置回收；提交成功或用户放弃后清理应用临时文件。CLI 已接收但模型执行失败时恢复待处理输入，不自动重发。

## 阶段 6：资源、恢复、安装与验收

- 顶部标签优先，溢出下拉；切换、隐藏不打断任务。后台闲置 10 分钟且完成、无草稿/等待/待处理输入、可恢复才释放。
- 网页释放前验证原链接与最新回答；失败保留。独立修复 b82890d 的恢复判据和过期操作隔离已集成；真实释放→恢复需最终验收。
- Pi 用原生 session 文件恢复原目录；Codex 全部驻留任务可释放时关闭共享服务，再按 thread 恢复。恢复不重发。退出不恢复任务列表，不另存完整聊天。
- 固定 bundle ID `local.mac-ai-prompt`，按构建机架构打包 `.app`，目前仅 arm64 通过验证。保留原 userData、网站分区、预设；默认不绑定快捷键，Option+Space 留给 Raycast。
- 安装到用户 Applications，更新保留旧应用。安装版复用本机钥匙串的固定 `Lasso Local Development` 证书签名，缺失时停止打包。首次跨机器安装需要授权，后续本机更新继续复用身份；辅助功能权限与开发 Electron 分开处理。
- 实现完成后先核对完整调用链和原方案，随后集中进行构建、协议、实际界面、原有划词、网页、图片、恢复及安装验收。未通过项按对应能力报告。

## 后续范围

0.3.0 已接入截图 S1，真实应用验收仍未完成；完整方案见 [截图 S1—S4](screenshot-implementation-plan.md)。完整截图须支持自动识别窗口/内部区域、截图或贴图上直接选字；优先复用免费开源产品。eSearch 的窗口框选、视觉边缘候选与图片文字覆盖层可参考，但不是现成独立组件。PixPin 的 Mac 内部控件识别中英文说明不一致，不能视为已经验证。保留现有 Shottr 工作流，不要求购买软件。

本轮不做 Claude、网站级提示词、多窗口、语音、Live2D、论坛入口。更多 bot、生图生视频继续留在路线图。

本地图片验收按用户后续确认，以 Codex 实际成功为准；Pi 保留原生图片支持及失败保护，不再尝试额外视觉模型。
